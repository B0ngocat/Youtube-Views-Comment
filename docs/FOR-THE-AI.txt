FOR THE AI ASSISTANT: how to use this handwriting server
=========================================================

The person who gave you this folder taught the Handwriting Engine their own handwriting. This folder lets you write
text or math in THEIR handwriting for them, and fill in PDF worksheets. You only need to run one program. You do not
need to host a website or use GitHub.

What is in this folder
  my-handwriting.json       their handwriting. PRIVATE: do not paste it anywhere, upload it, or put it on GitHub.
  handwriting-mcp.js        the server: write_text, write_batch, handwriting_status
  handwriting-mcp-pdf.js    the same, plus inspect_pdf and fill_pdf (read a PDF and write answers onto it)
  docs/handwriting-engine-guide.pdf   a plain guide for the person (you do not need it)

You need Node.js 18 or newer (check with:  node --version ). If it is missing, install it from https://nodejs.org .
Nothing else needs installing: the server is one file with no packages.

STEP 1. Start it as an MCP server. In your MCP settings, add a server like this (use the real full paths on this computer):

  {
    "mcpServers": {
      "handwriting": {
        "command": "node",
        "args": ["/FULL/PATH/handwriting-mcp-pdf.js", "--samples", "/FULL/PATH/my-handwriting.json", "--format", "svg"]
      }
    }
  }

  For Claude Code, the same thing as one command:
    claude mcp add handwriting -- node /FULL/PATH/handwriting-mcp-pdf.js --samples /FULL/PATH/my-handwriting.json --format svg

  Use handwriting-mcp.js instead if you only need to write text, not fill PDFs.
  The first call takes about 7 seconds (it learns the handwriting). After that it is fast.

STEP 2. Check it works: call the tool  handwriting_status . It should say how many words are loaded.
  If it says it cannot read the file, the path after --samples is wrong. Use the full path.

STEP 3. Use it.
  write_text   {"text": "The mean is 12.4", "kind": "text"}              one piece of writing
               {"text": "x = \\frac{a}{b}", "kind": "math"}              math (see below)
               optional: "format": "svg" | "png" | "both",  "seed": 2 (a different take),  "letter_height_pt": 10
               svg comes back as text (the SVG itself, ready to save as a .svg file). It is also saved to a file; the
               reply says where.
               "format": "note" makes a Notability note (.note) whose writing is editable pen strokes. It is saved to a
               file and returned as an embedded file. Tell the person to open it from Files with Share, then Notability.
  write_batch  {"items": [{"text": "one"}, {"text": "two"}]}              many at once. Use this, not a loop.
  inspect_pdf  {"pdf": "/path/worksheet.pdf"}                            where the text and the answer lines are
  fill_pdf     {"pdf": "/path/worksheet.pdf", "answers": [{"page": 1, "x": 72, "line_y": 192, "width": 468,
                "text": "My answer"}]}   saves a NEW pdf (the original is never changed). "line_y" is the y of the
                printed line the writing should sit on. Positions are in points from the top-left of the page.
               Add  "notability": true  to ALSO save a Notability note, <name>-filled.note: the worksheet is its pages and
                the answers are editable pen strokes on top (optional "pen_width", default 1.05). Use it when the
                person wants to work on the worksheet in Notability. Tell them to open it from Files with Share, then
                Notability. Rotated pages are not supported.

Characters with no sample: every character is checked BEFORE anything is drawn. If the person never wrote one (a degree sign,
  a macron, a digit they skipped), write_text, write_batch and fill_pdf STOP and tell you which characters and which words (and
  which answer or item) contain them. Nothing is skipped or guessed. Then either ask the person to teach them, change the text,
  or call again with  "on_missing": "fallback"  to draw a clean stand-in for symbols and punctuation that have one (the reply lists
  them: they are NOT the person's handwriting, so tell the person). Letters and digits can never be faked. handwriting_status
  with  "check": "<your text>"  tells you in advance.

Fitting an answer to its box (fill_pdf): too long for the box means, in this order: it wraps onto more lines inside the width,
  the box grows downward (up to "max_height"; by default it stops above the nearest printed text under the box; "grow": false
  forbids it), and only as a last resort are the letters made smaller, never below "min_size_ratio" (default 0.8) of the size you
  asked for. The report says for every answer: fits as it is / WRAPPED / box GROWN / SHRUNK / DOES NOT FIT. Read it. If it says
  DOES NOT FIT, or SHRUNK to a size that looks different from the other answers on the page, make the box taller or wider or
  shorten the text; do not hand in a page where answers are at visibly different sizes. Wrapped lines do not follow the printed
  ruled lines under the box, so look at the page.

Spanish: send the text with its real characters, for example  "text": "¿Cómo estás? ¡Qué día! Mañana vamos al pingüino."
  The accents (á é í ó ú ü), ñ, the capitals (Á É Í Ó Ú Ñ) and the upside-down ¿ ¡ all work. They are drawn in the
  person's own style if they wrote them, and otherwise as their plain letter with an accent drawn over it. Do not strip
  the accents and do not replace them with a different spelling. Look at the result: check that every accent is over
  the right letter and that ñ has its tilde.

Math input:  x^2   x_1   \frac{a}{b}   \sqrt{x} or sqrt(x)   \sqrt[3]{x} or cubert(x)   \int_0^1   \sum_{i=1}^{n}
  \text{ words }   for plain words inside math.     "\ " (backslash space) for a space that stays.
  Ordinary spaces inside math are ignored, like in TeX.

Digits: they are the weakest part, and now less wobbly in dense math (digits are brought to the person's usual size and baseline,
  operators sit in the middle of a digit with room round them, digits are spaced the way the person spaces their own numbers so they
  no longer touch, a decimal point keeps a gap). If their × is written too small to read it is left out and handwriting_status says
  "× (written too small to read)": use on_missing "fallback" for a clean one, and say so. Still look at every number. If digits look off, say which,
  and the person can do the Teach tab rounds x and y, dy/dx and calculus, More numbers, and x, y and digits again: a number written
  there is written back whole when you type it (use math kind, or plain text with the word_reuse option up).

Seeds: write_text, write_batch and fill_pdf take "seed" (a whole number from 0; in fill_pdf an answer with none gets its own seed from where it sits on the page, so answers with the same words do not open alike and the report says "own seed N"; write_text and write_batch default to 1). The same
  seed is the same writing; another seed is another take. For digits another seed picks another of the person's clean examples, so
  to re-roll one bad digit, change the seed of that answer. fill_pdf says (seed N) in the report when you gave one.
Previews: fill_pdf with "preview": "digits" (or "all") returns a small picture of each answer's ink (5 to 10 KB each) so you can check
  digits without rendering and cropping whole pages. It shows the writing only, not the page behind it.
Math TeX: only the commands in handwriting_status {"math_help": true} work (arrows \Rightarrow \implies \iff, sets \in \cup, \bar \vec \hat,
  primes y' f'', Greek, \frac \sqrt \int \sum ...). Anything else is refused with a short message and suggestions, never written out
  as a word. Symbols the person never wrote are drawn as clean stand-ins and the reply says so; Greek letters need the person's own.

Up and down: every line of writing slides a little above and below the line (a slow wave, each word a little up or down, a slight bounce
  from letter to letter), so it does not sit on a typeset baseline. "bounce" (0 to 3, default 1.5) on write_text, write_batch and fill_pdf
  changes it; 0 is straight across. It is the person's chosen amount: do not turn it to 0 to make the page look tidier.
Marks and capitals: tildes and other accents are one smooth stroke, drawn fresh each time (length, angle and curve change). A letter the
  person has only a few examples of (a capital X, the E and L that open a line) is turned and stretched a little each time it is used, so
  X marks and line openings are not stamps. If two seeds give the same digit, the report says so when a digit has only one or two clean
  examples (digit N: only K clean examples): tell the person, do not pretend it was re-rolled.
Fills that read as handwriting, not as typed text turned into handwriting: write short answers, not full-width tidy lines; give each answer its own
  place and, if wanted, "stagger": true (starts it a little in from the left, differently each time); no dashes or hyphens as separators in
  prose, use commas; EM DASHES ARE REFUSED by the tools (use a comma, a full stop or a new sentence).

Marks (fill_pdf "marks"): what a person does with a pen besides writing words. Drawn wobbly, in the same pen and ink as the writing,
  the same for the same seed, and each mark that has no "seed" gets its own from where it sits, so two circles are never alike.
  answers may be left out when there are marks. All marks are checked before anything is drawn.
    circle     a loop round the target (a little bigger, a little tilted, not quite closed)    tick   a check mark in the target
    cross      an X in the target       underline  a line under it      strike  a line through it (crossing out)
    box        a rectangle round it     arrow, line  from x1,y1 to x2,y2 (the arrow head is at x2,y2)
  Aim a mark at printed text:  {"page": 1, "type": "circle", "text": "B)"}  (exact text first, then ignoring case and extra spaces;
  "nth": 2 for the second match on the page; with several matches and no nth the first is used and the report says "first of N
  matches"; if it is not printed on that page the call stops and lists the closest printed lines), or at a rectangle in points from
  the page's top-left: {"page": 1, "type": "tick", "x": 72, "y": 410, "width": 12, "height": 12}. A tick or cross with only x and y
  gets a square of about 1.4 x the letter height whose top-left corner is x,y. inspect_pdf lists checkbox-like squares as
  "box  x= y= w= h=": aim a tick at one of those. Give "letter_height_pt" when the writing on the page is not the default 9.5.
  Circle an option:
    fill_pdf {"pdf": "/path/quiz.pdf", "marks": [{"page": 1, "type": "circle", "text": "B)"}]}
  Tick a box and write an answer on the same page:
    fill_pdf {"pdf": "/path/form.pdf", "marks": [{"page": 1, "type": "tick", "x": 72, "y": 410, "width": 12, "height": 12}],
              "answers": [{"page": 1, "x": 72, "line_y": 192, "width": 468, "text": "Because it is heavier"}]}
  The report has one line per mark, for example: mark 1 (page 1): circle round "B)" at x 212.4, y 318.0, 14.2 x 11.0 pt. The text's
  rectangle is found from the PDF's own text items; inside one item the position of a short piece is an estimate, so look at the page
  (a circle that cuts through a letter or sits half a letter off: aim it with a rectangle instead). With notability: true the marks
  are pen strokes in the note too.

Rules
  - Look at every result before you hand it over. Digits are the weakest part: check numbers carefully.
  - If a character has no sample, the tool says so. Do not guess; tell the person.
  - Write only what the person asked for. Do not fill in their name or anything else they did not give you.
  - Whether it is okay to hand in work written this way is the person's decision, under their school's or workplace's rules.
  - If a letter keeps coming out wrong, the person can fix it in the website (Write tab, "Fix mode") and download a new zip.
